Note on Tauri vs. Playwright

PrivateVoice is a Tauri 2 desktop app that uses native WebKit for rendering in production. Playwright tests run in Chromium, which may exhibit minor rendering differences from WebKit (e.g., font metrics, CSS animation timing, scroll behavior). The visual validation here confirms structural layout correctness — pixel-perfect matching against WebKit would require Tauri-native testing infrastructure.

6. Issues Found & Fixes Applied

#1
Help panel screenshots showed thin sliver at all resolutions FIXED
Root cause: E2E test captured screenshot during 0.3s CSS animate-slide-left animation. The test used .isVisible() (instant check) instead of expect().toBeVisible() (auto-retry wait).
Fix: Updated test to wait for heading visibility + 400ms animation settle. Added animation-fill-mode: forwards to CSS. Added overflow-x-hidden to prevent content overflow.
Files changed: e2e/visual-validation.spec.ts, src/lib/components/help/HelpPanel.svelte, src/lib/components/settings/SettingsPanel.svelte
#2
Generate button below viewport at 900×650 KNOWN
The Generate button's bottom edge sits at y≈849 in Custom Voice mode, below the 650px viewport. Users must scroll to access it.
Mitigation: Test validates the button exists in the DOM and is scrollable-to. The test uses scrollIntoViewIfNeeded() before interaction.
Recommendation: Consider 1024×768 as the documented minimum supported resolution, or implement a collapsible voice selector to reduce vertical space.
#3
Settings panel right-edge text truncation COSMETIC
GPU name ("Apple Si...") and Memory values ("Detecting...") truncate at the right edge of the settings panel at all resolutions. The "Browse" button for Export Folder is slightly clipped at 900x650.
Impact: Low — values are still identifiable. Truncation is a standard overflow behavior for long text in fixed-width panels.
Future fix: Add text-overflow: ellipsis or use a responsive layout for the key-value rows.
#4
Left panel narrow at 1920×1080 LAYOUT NOTE
At 1920px width, the input panel occupies ∼19% of screen width while the output panel is largely empty space with a centered placeholder. This is functional but not optimal for large displays.
Recommendation: For future responsive work, consider scaling the left panel width proportionally at wider viewports, or implement a flexible split-pane layout.
#5
Library FAB overlaps voice card text at 900×650 MINOR
The floating library button (bottom-left corner) partially covers the "Vivian" voice card description text at 900x650.
Impact: Very low — the button is a small icon and the overlap is minimal. Voice card is still tappable around it.
Recommendation: No action needed for v1.0. Can be addressed in a responsive refinement pass.

8. Recommendations

For v1.0 Release

  • All critical and major issues have been fixed. The test suite is green (90/90).
  • Document 1280×800 as the recommended minimum resolution in user-facing docs.
  • The current UI works well from 1280×800 through 1920×1080, covering the vast majority of macOS users.

Post-v1.0 Responsive Improvements

  • Flexible left panel width: Scale the input panel proportionally at viewports wider than 1440px to reduce empty space.
  • Collapsible voice selector: At viewports under 800px height, collapse the voice card grid to reduce vertical space and keep the Generate button in view.
  • Settings key-value layout: Use responsive flex layout for settings rows to prevent right-edge text truncation.
  • WebKit-specific testing: Consider adding Playwright WebKit browser tests alongside Chromium to catch rendering differences before they reach production Tauri builds.
  • Cross-platform resolution testing: When Linux/Windows builds are ready, validate at common non-Retina resolutions (1366×768, 1600×900) that differ from macOS display scaling.
